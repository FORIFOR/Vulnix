# 新しいアクセス制御の保留条件（隔離ラボ）

PR #85統合候補を基点に、既存の7条件とは別のHTTP対象を4条件追加した。模擬対象は `tests/fixtures/access_fresh_holdout_lab.py` にあり、診断器・正解表をimportしない。所有者契約と正解ラベルは別のJSONに置き、ARTEXとローカル模擬モデルには渡さない。対象ホスト・URL・認証情報・本文・正解ラベルは外部AIへ送っていない。全対象はループバックの模擬環境で、実サイトL2と有料モデル呼び出しはない。

条件は、HTTP 200の認証拒否＋`request_id`、公開仕様の個人情報風JSON、別アカウント資源の404拒否、別アカウント資源の200許可である。後者だけをIDOR `proven` とし、正解情報を実行器から分離した。

最初の実測では、認証拒否＋短い `request_id` が保護データの取得として誤検知された。`aegis/service_diag.py` は拒否本文の固定キー以外を認めず、管理者仕様が認証必須ならHTTP 200 JSONを `detected` にしていた。正解ラベルを変えず、短い英数字等の要求IDだけを拒否本文の付随情報として許容し、`private` などの別項目は引き続き拒否本文扱いにしない修正を行った。
