# 初期計画の混合条件（隔離ラボ）

`tests/fixtures/initial_mixed_holdout_truth.json` は診断器とは別に、CORS と Cookie の基本所見、Apache 追加検査の適切さ、実際の `mod_status` 露出の有無を定義する。対象はローカル HTTPS の5条件で、既存の応答条件と Apache バナー・追加検査同意を新しく組み合わせた保留用条件である。ARTEX/モデルには条件ID、正解ラベル、ホスト名、URL、応答本文を渡さない。これは**新しい脆弱性分類や未知のWeb応答の検証ではない**。

固定診断、一律計画、初期観測による選択を各条件で比較する。一律計画と初期観測による計画は、許可された項目だけをGateway・隔離Workerで実行する。評価用の模擬モデルはApache `mod_status` を一律に提案し、実AIの判断能力は測れない。Linux CIでは実ARTEXバイナリとローカル模擬モデルを用いた代表2条件も実行する。

## macOS、ARTEX互換プロセス、ローカル模擬モデルでの単発測定

| 指標（5条件合計） | 固定 | 一律計画 | 観測選択 |
| --- | ---: | ---: | ---: |
| 基本所見 TP / FP / FN / TN | 2 / 0 / 0 / 3 | 2 / 0 / 0 / 3 | 2 / 0 / 0 / 3 |
| 追加検査の選択 TP / FP / FN / TN | 0 / 0 / 3 / 2 | 3 / 2 / 0 / 0 | 3 / 0 / 0 / 2 |
| 不要な提案 / 必要な検査の省略 | 0 / 3 | 2 / 0 | 0 / 0 |
| 対象GET / Worker起動 | 5 / 5 | 8 / 8 | 8 / 8 |
| 計画起動 | 0 | 5 | 3 |
| 診断完了時間の合計 | 0.408秒 | 3.159秒 | 2.176秒 |

ローカル互換プロセスは `fake_intents` を受け取るため、モデル呼び出しは0回である。表の時間は各条件の診断開始から完了までの合計で、証明書生成や所有確認の準備は含まない。測定値は実ARTEXやAbliteration AIの時間・費用に一般化できない。実モデルのトークン・料金・判断精度は未測定である。既存の5分類横断比較にはこの保留用条件を混ぜず、分類別とMacro平均の条件数を維持する。

再現方法：`VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_initial_mixed_holdout`。Linux CIの代表条件は `--smoke` で実行し、JSONを `artex-real-planner-evidence` に保存する。
