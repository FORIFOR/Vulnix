### 1つの項目だけで正解を当てられるか（間接的な漏えいの確認）

モデルに見える項目を1つだけ選び、その値ごとに最も多い正解を答える表を作ったとします。その表で何件当たるかを数えました。

| 比較対象 | 正解数（60件中） |
| --- | --- |
| 常に最も多い正解を答える | 35 |
| 最も当たる項目（`server_family`） | 38 |
| メモの有無、メモの長さ、Cookieの数 | 36 以下 |

どの項目を使っても、常に同じ答えを返す場合より、当たる件数は最大3件しか増えません。1つの項目だけで正解が分かるような漏えいはありませんでした。

### 漏えいではないが、評価結果を偏らせる要因（隠さず記録します）

1. **メモの有無と正解に相関があります。**

   | | 検査が必要な条件 |
   | --- | --- |
   | メモあり | 16/28（57%） |
   | メモなし | 9/32（28%） |

   「メモがあれば何か検査する」という単純な方法でも、ある程度は当たってしまいます。
2. **作成者は、規則A/B/B2/Eを書いた後に条件を作りました。** そのため、Eが誤った10件は作成者が意図して作ったものです。たとえば否定表現（「本人以外が閲覧しても問題のない」）です。60条件は無作為に集めたものではなく、メモの解釈が難しい条件を多めに含めています。数値は、実際のサイトでの割合を推定したものではありません。
3. **方式Dの指示文に、データの設計が反映されています。** 「メモは構造化項目を補足・訂正・否定することがある」と書いており、これは作成者がデータを知ったうえで書いた助言です。実AIの評価では、この助言がAIに有利に働くおそれがあります。指示文を変えると要求SHAが変わるため、今回は変更していません。
4. **H053のメモは、検査を明示的に求めています**（「本当に無効になっているか確認したい」）。メモが答えを直接言っている例で、1件です。
5. **ラベルが1人の判断です。** 判定が分かれやすい条件があります（§3）。

「少なくとも7件」とした理由：メモを読まない規則は、構造化された項目が同じ条件に同じ答えしか返せません。各組の中で正解が最も多い答えを選んでも、残りは誤りになります。その最小数が7件です。どの7件になるかは、規則がどの答えを選ぶかで変わるため、特定のケースには決まりません。

## 4. 独立再判定のための資料（`docs/adaptive_holdout_v2_relabel/`）

実施する人向けの手順（判定者と裁定者の条件、判断不能の扱い、裁定のしかた）は [ADAPTIVE_HOLDOUT_V2_RELABEL_PROTOCOL.md](ADAPTIVE_HOLDOUT_V2_RELABEL_PROTOCOL.md) にあります。判定者向けの指示書には、判定基準と項目の意味（中立的な説明）を載せ、`unsure`（判断できない）という回答を受け付けます。

| パス | 内容 | 判定する人に渡すか |
| --- | --- | --- |
| `full/` | 60件すべて。並びをシャッフルし、ID を `A01`〜`A60` に付け替えたもの | 渡す |
| `focus/` | 上の30件に、それ以外からの10件を混ぜた40件。ID は `B01`〜`B40` | 渡す（どれが重点の条件かは分からない） |
| `*/INSTRUCTIONS.md` | 問い、検査の定義、回答方法 | 渡す |
| `*/answers_template.csv` | 回答用の表（選んだ検査、省いた場合に重大か、確信度 `high`/`medium`/`low`/`unsure`、理由） | 渡す |
| `KEY_DO_NOT_SHARE_WITH_REVIEWERS.json` | 付け替えたIDと元のケースIDの対応表（正解は含まない） | **渡さない** |
| `PACKET_SHA256.json` | 資料の各ファイルのハッシュ | — |

### 運用上の条件

- 判定する人には `full/` か `focus/` のフォルダだけを渡してください（ZIPなど）。リポジトリへのアクセス権は渡さないでください。リポジトリにある `truth.json` や、この資料を見れば正解が分かってしまうためです。
- 指示書には、作成者の判定基準（`ADAPTIVE_HOLDOUT_V2.md` の§2）を入れていません。各検査の中立的な定義だけを載せています。

### 判定者に何も漏れていないことの確認（テスト）

- 資料の各条件には、`blind_id`、`category`、`observation`、`owner_spec`、`allowed_catalog_ids` だけが入っています。
- 正解の項目名、判定理由、元のケースIDは含まれません。
- 規則の名前（A/B/B2/E）、規則の選択結果、模擬モデル（C）や実AI（D）の予測、F1などの数値も含まれません。
- 回答用の表は、すべて空欄の状態で配ります。
- ブラインドIDの並びと元の並びの相関は0.4未満です。
- `KEY_DO_NOT_SHARE_WITH_REVIEWERS.json` には、正解も重点の条件の一覧も含まれません。

### 回答後の集計

```
VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.audit_adaptive_holdout compare --answers answers.csv
```

次の値を出力します。

- 作成者のラベルとの一致率と、Cohen の κ（組単位）
- ラベルが食い違った条件の一覧
- 判定者のラベルを正解として、A/B/B2/E を採点し直した結果（重大な条件は、判定者の `serious_if_skipped` で決めます）

許可されていない検査を選んだ回答は、取り込まずにエラーにします。

### テスト（`tests/test_adaptive_holdout.py` の `TestAuditAndBlindPacket`）

- 資料に、正解の項目名・判定理由・元のケースIDが含まれないことを確認します。
- 対応表に、正解や重点の条件の一覧が含まれないことを確認します。
- 資料をもう一度生成すると、コミットされている資料と同じハッシュになることを確認します。
- 集計ツールが、食い違いの検出と、許可されていない検査の拒否を正しく行うことを確認します。
- テストの作成中に、`full` と `focus` のIDの頭文字が両方とも `F` で重なる不具合が見つかり、直しました。
