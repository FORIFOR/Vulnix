# Apache観測事実の初回利用

PR #82でアカウント資源の観測事実から重複した `list_facts` を省けたため、別の観測条件でも比較する。対象は独立したローカルHTTPSのApache情報露出5条件で、既存の正解ラベルと同意条件をそのまま使う。初期観測で得た匿名化済み `server_family` がARTEXの最初のグラフ要約にある場合に直接計画する方式と、毎回 `list_facts` を呼ぶ方式を比較する。

模擬モデルにはホスト名、URL、認証情報、応答本文、正解ラベル、条件IDを渡さない。計画はVulnixのカタログ照合とGatewayを通り、実行は隔離Workerだけが行う。同意なしでは `/server-status?auto` を取得せず、検出TP/FP/FN/TNの分母から外して選択安全性にだけ含める。

macOSのARTEX互換代役による5条件の単発測定では、両方式とも検査選択TP/FP/FN/TNは3/0/0/2、情報露出判定は1/0/0/3、対象GETとWorker起動は各8回、計画起動は3回で一致した。同意なし1条件は追加GETなし。代役はモデルを呼ばず、呼び出し数やトークン削減の証拠にはならない。Linux CIで実ARTEXとローカル規則型モデルを使う代表条件を別途測る。

この比較は既存の模擬モデルの余分な取得を調べるもので、実Abliteration AIが未知の対象を判断できる証拠ではない。費用欄は外部モデルの実請求額ではなく、Gatewayの予算用推定値として分けて記録する。実サイトL2禁止と実サイトへの新規診断通信の制限は維持する。

再現：`VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_status_first_prompt`。
