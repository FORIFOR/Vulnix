# PR3: Cloud Run OIDC 所有確認の最小設計

## 信頼境界

Cloud Run の OIDC ID トークンはサービスアカウントの主体を示すが、それだけでは任意のホストの管理権限を示さない。所有確認には、管理者があらかじめ組織と登録済み HTTPS 443 ホストに紐付けたサービスアカウント sub と、そのホストの公開 head に置かれた短命の challenge の両方を要求する。

`aegis/cloud_run_ownership.py` は判定を担当し、`aegis/cloud_run_store.py` が組織ごとの登録主体と短命チャレンジをSQLiteで保持する。`google-auth` がGoogle公開鍵で署名・期限・audienceを検証する。所有証明は既存の `AssessmentService` の署名付き台帳に記録し、診断範囲確認とL2の別人承認は別工程として維持する。Cloud RunのIAM認証用audience（サービスURL）と、所有証明用audience（`urn:vulnix:cloud-run-proof:...`）は別である。

## 手順

1. 認証済み依頼者が、組織と登録済みホストに対して challenge を発行する。サーバーは依頼者、組織、ホスト、登録済み主体、OIDC audience、有効期限を一緒に保持する。有効期限は5分。
2. Cloud Run 側は指定された audience で ID トークンを生成し、登録ホストのトップページの head に challenge の meta タグを置く。
3. サーバーは認証済み依頼者と組織メンバーシップを確認してから、組織・ホスト・依頼者・登録バージョンが一致する challenge だけをSQLiteの原子的トランザクションで消費する。別の依頼者のチャレンジは消費しない。Google署名検証済み ID トークンの発行者・audience・主体・時刻を確認する。
4. 登録ホストの HTTPS 443 に証明を取りに行く。TLS 証明書検証と公開 IP へのピン留めを行い、リダイレクトは追わない。head 内の token 完全一致だけを採用する。
5. いずれかが失敗すれば証明は成立せず、消費済み challenge は再利用できない。未消費の challenge は再起動後も期限まで保持し、期限切れは発行・消費時に削除する。組織あたり未消費20件、依頼者あたり1時間30件、組織全体で1時間100件を上限とする。主体の変更・解除は保留中の challenge と既存の診断権限を失効させる。

## 未確認

Cloud Run 実環境で生成したトークン形式と所有証明用audienceの互換性は未確認。実サービスへの通信やデプロイはこのPRでは行わない。ローカルの模擬鍵と模擬応答による署名・API・台帳検証を実施する。
