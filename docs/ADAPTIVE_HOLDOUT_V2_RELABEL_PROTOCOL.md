# adaptive_holdout_v2 独立再判定の手順（実施する人向け）

2026-11-19 JST。**独立判定はまだ実施していません。** 現在の F1 などの値（A 0.000 / B 0.471 / B2 0.723 / E 0.793）は、データ作成者のラベルに対する**暫定値**です。

判定者に渡す資料（判定基準・項目の意味・回答方法・判断不能時の扱い）は、`docs/adaptive_holdout_v2_relabel/{full,focus}/INSTRUCTIONS.md` にあります。この文書は、判定を実施する人（コーディネーター）が使う手順書です。

## 1. 役割

| 役割 | 条件 |
| --- | --- |
| 判定者（2人以上、3人を推奨） | ・データ作成者ではない（このリポジトリの作業エージェントも作成者に含む）<br>・`truth.json`、作成者の資料、評価結果を見ていない<br>・少なくとも1人は、Webセキュリティの実務経験がある |
| 裁定者（1人） | ・データ作成者ではない<br>・判定者と兼ねないことを推奨 |
| コーディネーター | ・資料を配り、回答を回収して集計する<br>・判定の内容には関与しない |

ツールは、判定者や裁定者の名前が `author`、`claude`、`dataset-author` の場合、受け付けずにエラーにします。

## 2. 手順

1. **資料の確認**：`PACKET_SHA256.json` のハッシュと、配る資料のハッシュが一致することを確かめます。
2. **配布**：判定者ごとに、`full/` か `focus/` のフォルダだけを渡します（ZIPなど）。
   - リポジトリへのアクセス、`KEY_DO_NOT_SHARE_WITH_REVIEWERS.json`、この文書は渡しません。
   - `focus/` は、重点30件に、それ以外の10件を混ぜた40件です。判定者には、どれが重点の条件かは分かりません。
   - 全員が同じフォルダで回答すると、比較しやすくなります。
3. **個別の回答**：判定者は、互いに相談せず、生成AIも使わずに回答します。回答期限を決めておきます。
4. **個人ごとの集計**：判定者ごとに、作成者のラベルとの一致度を確かめます。

   ```
   python3 -m scripts.audit_adaptive_holdout compare --answers r1.csv
   ```

5. **統合**：

   ```
   python3 -m scripts.audit_adaptive_holdout adjudicate --answers r1.csv r2.csv [r3.csv] --reviewers r1 r2 [r3]
   ```

   - **一致**として確定する条件：その条件で `unsure` 以外を答えた判定者が2人以上いて、全員の選択（検査の組み合わせ）と「省くと重大か」が一致していること。
   - それ以外（意見が分かれた、判断できる回答が1人以下）は、**保留**として一覧に出ます。保留が残っている間は、終了コードが2になり、ラベルは確定しません。
6. **裁定**：裁定者が、保留になった条件だけを `adjudication.csv` に記入します。

   | 列 | 記入内容 |
   | --- | --- |
   | `blind_id` | 対象の条件 |
   | `decision` | `label` または `ambiguous` |
   | `selected` | `label` の場合、選ぶ検査ID |
   | `serious_if_skipped` | `yes` / `no` |
   | `adjudicator` | 裁定者の名前 |
   | `reason` | 理由（必須） |

   - 裁定者は、判定者全員の回答と理由を見て決めます。作成者のラベルと理由は見せません。
   - `ambiguous` にした条件は、主要な指標から外し、件数と一覧を別に報告します。
7. **確定**：`--adjudication adjudication.csv --out independent_labels.json` を付けて再実行し、保留が0件になれば確定です。
   - 出力には、`labels_sha256`、独立したラベルで採点し直した A/B/B2/E、同じ条件を作成者のラベルで採点した値が入ります。
   - 確定したラベルは `tests/fixtures/adaptive_holdout_v2/truth_independent.json` として新しく追加し、manifest にSHA-256を記録します。既存の `truth.json` は上書きしません。

## 3. 判断不能（unsure）の扱い

| 場面 | 扱い |
| --- | --- |
| 判定者が `unsure` と答えた | その判定者は、その条件で「判断なし」として扱います（「検査不要」とは数えません）。判定者どうしの一致度（κ）の計算からも外します |
| `unsure` 以外の回答が2人に満たない | 保留にし、裁定に回します |
| 裁定でも決められない | `ambiguous` として主要な指標から外し、件数を報告します。重大な条件の多くが `ambiguous` になった場合は、データセットそのものの見直しが必要です |
| 空欄の行 | 未回答として扱います。`unsure` とは区別します |

## 4. 結果の使い方

- 判定者どうしの一致度（κ）が低い場合（目安は0.4未満）は、判定の問い自体が曖昧であるとみなし、条件を作り直します。
- 実AIの評価（方式D）は、独立ラベルを確定してから送信することを推奨します。確定前に送信した場合、その結果は作成者のラベルによる暫定値として扱います。
- 独立ラベルで採点した結果、規則Eが最強の基準でなくなった場合は、AIを採用する基準（「最強の非AI規則を上回ること」）の比較相手を差し替えます。
