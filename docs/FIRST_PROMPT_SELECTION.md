# 初期観測事実の単回利用（隔離ラボ）

ARTEXの初回グラフ要約には、初期観測から記録した事実の表題が既に含まれる。認証・IDOR保留用7条件では、従来のローカル模擬モデルはその事実が見えていても `list_facts` を必ず1回呼んでいた。今回の比較では、要約に必要な事実がある場合に直接検査を提案し、ない場合だけ `list_facts` を呼ぶ。ARTEXのツール許可範囲、Gateway審査、隔離Worker、権限と証拠の判定は変更しない。

独立正解表と所有者仕様は既存の `access_holdout_truth.json` と `access_holdout_owner_specs.json` を使用する。二方式を同じ7対象に適用し、検査選択、認証必須JSONとIDORの検出、対象GET、Worker、計画起動、模擬モデルへの要求数、Gatewayの予算用推定トークン、時間を比較する。正解表、条件ID、HTTP応答本文はモデルに渡さない。IDOR再現は隔離ラボ内だけである。

macOSのARTEX互換代役では、7条件について検査選択TP/FP/FN/TNが両方式とも3/1/0/3、認証必須JSONの検出が1/0/0/6、IDORが1/0/0/6、対象GETが13回、Worker起動が11回、計画起動が7回で一致した。代役はモデルを呼ばないため、呼び出し・トークン削減の根拠には使わない。Linux CIでは本物のARTEXとローカル模擬モデルで代表3条件を比較する。

初期のアカウント資源事実を意図的に欠かした追加条件も別に実行する。この条件では所有者仕様によるルートの所見を維持し、IDORを作らず、実ARTEX経路で必要時の `list_facts` を確認する。これは7条件の精度集計には混ぜない。

模擬モデルは固定の選択規則を用いる。実Abliteration AIが初期要約から同等の判断をするか、未知の語彙・構造で性能を維持するかは未検証である。予算用推定トークンは実使用量や請求額ではない。実サイト診断、外部AI送信、L2の許可範囲は変更していない。

再現：`VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_first_prompt_selection`。Linux CIの `--smoke` は実ARTEXバイナリとローカル模擬モデルを用いる。
