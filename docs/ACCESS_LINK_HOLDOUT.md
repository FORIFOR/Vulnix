# 未知のLink表記によるアクセス制御の保留条件

既存の7条件とは別の隔離対象で、初期応答の `Link` 表記を変えた7条件を評価する。正解ラベルと所有者仕様は診断器から独立したJSONに保存し、ARTEXや模擬モデルには渡さない。模擬モデルに見えるのは、実測から作ったアカウント資源リンクの `present` / `absent` だけである。対象ホスト、URL、認証情報、応答本文、正解ラベルは外部AIへ送らない。

有効な別表記3条件（パラメータ順序と空白、カンマ区切りの値、繰り返すヘッダー）と、紛らわしい4条件（似た関係名、別ホスト、引用符内のカンマ、繰り返す無関係ヘッダー）を用意した。認証済み所有者と別アカウントの資源応答を照合できた場合だけIDORを `proven` とする。HTTP 200の拒否本文を漏えいとして扱わない。

同じ7条件で、従来の完全一致解析と、Link値を区切って固定の相対パス・関係名だけを認める解析を比較した。Workerは繰り返す `Link` ヘッダーを1つの値に安全に連結し、観測前の欠落を防ぐ。macOSのARTEX互換代役と固定応答モデルでの単発測定は次のとおり。

| 指標 | 従来の完全一致 | Link項目の解析 |
| --- | ---: | ---: |
| 検査選択 TP/FP/FN/TN | 0/0/3/4 | 3/0/0/4 |
| IDOR判定 TP/FP/FN/TN | 0/0/2/5 | 2/0/0/5 |
| 対象GET | 7 | 13 |
| Worker起動 | 7 | 10 |
| ARTEX計画起動 | 7 | 7 |
| 経過時間の合計 | 4.021秒 | 4.222秒 |

追加通信と時間は、以前見逃した適用可能な検査を実施した分である。7条件の狭い結果から一般サイトのPrecision・Recallを推定しない。代役プロセスではモデル呼び出しとトークンが0なので、実ARTEXとローカル模擬モデルの代表条件はLinux CIで別途計測する。実Abliteration AIは未使用であり、モデル自身の未知構造理解を証明していない。

このLink解析は既存のローカルラボ用ARTEX観測経路に限る。実サイトのL2禁止、所有確認、範囲制限、Gateway、Workerの実行権限は変更していない。再現：`VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_access_link_holdout`。
