# v4 で見逃したケースの分析（v5 のサイクルの出発点）

2026-11-22。凍結した判定器（[FROZEN_JUDGE_V4.md](FROZEN_JUDGE_V4.md)）が v4 で見逃した9件を、`comparison_holdout_v4.json` の手順の記録とケースの定義から分類しました。

**この分析をもとに判定器を変える場合、v4 は開発用に移します。** 改善した判定器は、改めて凍結した後で、新しい未見セット（v5）を作って1回だけ評価します。

| 原因 | ケース | 判定（規則） | 方針 |
| --- | --- | --- | --- |
| 標準的な API の形（JSON:API の `data.attributes`、GraphQL の `data.account`、HAL の `_embedded`）で、ID は親のオブジェクトに、機密の値は子のオブジェクトにある。案2は「1つのオブジェクトが両方を欄として直接持つ」ことを求めるため、一致しない | 021、038、039（006 の修正前） | 判断不能（`unrecognised_answer`） | **改善の候補**：ID を直接持つオブジェクトの子孫のうち、**一覧（配列）を経由しない**子のオブジェクトにある目印も、同じ記録とみなす。配列の別々の要素に分かれる場合（誤検知の形）は、引き続き不可とする |
| 本文が 4 KB を超え、Worker が切り詰めた（B の記録が先頭にある場合と、後ろにある場合） | 026、031 | 判断不能 | **改善の候補**：L2 の IDOR 検査に限り、Worker が保持する本文の上限を引き上げる（例：64 KB）。証拠のサイズと、記録の保存の影響を確かめる。Worker の変更になるので、独立したレビューを必須にする |
| 修正後の GraphQL のエラー（`errors[]` に `path`・`locations`・`extensions` がある）を、拒否と認識できない | 006（修正後） | 判断不能 | **改善の候補**：`errors` の要素に、スカラー値か、スカラー値の一覧だけからなる `path`・`locations`・`extensions` も認める |
| 記録が JSON の文字列として埋め込まれている | 020 | 判断不能 | **変えない**：独立したセキュリティレビューで、誤検知の形として塞いだもの。保留は安全側なので、見逃しとして受け入れる |
| 所有者本人の対照が取れない（B 本人の要求が 500・429） | 009、016 | 判断不能（`control_failed`） | **変えない**：比較の基準がないため、保留が正しい。2人の判定者とも「保留が妥当」と判定している |

## 改善した場合の評価の手順

1. 判定器を変更し、v1〜v4 と単体テストの誤検知の回帰をすべて確かめる。
2. 判定器、正規化、閾値、採点を凍結する（`FROZEN_JUDGE_V5.md`）。
3. 判定器を実行せずに v5 を作り、ハッシュを記録する。2人目の判定者が、正解を見ずにラベルを付ける。
4. v5 を1回だけ評価し、改善の前（v4 を凍結した判定器）と後を、同じ v5 で比べる。
5. 人による確認と署名は、人のレビュー者が行う。
