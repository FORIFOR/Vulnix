- 正解は [LABEL_REVIEW_SHEET.md](LABEL_REVIEW_SHEET.md) の判定の基準だけで付けました。「判定器が証明できること」ではなく、「サーバーが実際に A・匿名に何を返し、所有者が何を求めているか」です。ケースごとの根拠は [holdout_v4_author_notes.md](holdout_v4_author_notes.md) にあります（どのコードも読みません）。
- v1〜v3 の応答の形は使っていません。

### 評価の前に記録した、判断が分かれうるラベル

結果を見る前に、作成者が迷った点を書いておきます。

- **JSON の文字列の中の B の記録**（`record_in_string`）：文字列を JSON として読めば B の記録全体なので、**成立・保留は不適切**にしました（v3 の base64 と同じ考え方）。
- **B の記録の後に長い履歴**（`long_b_first`）：本文は 4 KB を超えますが、B の ID・所有者・機密の値はすべて最初の 4 KB にあるので、**成立・保留は不適切**にしました。「本文を最後まで読めていない」として保留を妥当とみる立場もありえます。
- **A の記録だけの長い一覧**（`long_a_only`）：実際には B の記録はありませんが、保持する 4 KB からは後ろに B の記録がないと言えないので、**不成立・保留が妥当**にしました。
- **4 KB の後に B の記録**（`long_list_b_late`）：サーバーは B の記録を返していますが、保持する範囲に現れないので、**成立・保留が妥当**にしました。
- **A のページで「res_b_001 は acct_B のもの」と書く**（`html_a_escaped`）：所有関係の露出はありますが機密の値はないので、**不成立**にしました（v3 の伏せ字の B の記録と同じ考え方）。
- **200 の「リクエストが多すぎます」**（`soft_rate_limit`）：状態コードは 200 でも回数制限なので、v1・v3 の 429 と同じく**不成立・保留が妥当**にしました。
- **修正で形式だけ変わった**（`owners_array` → `jsonapi_secret`）：A はまだ B の記録を受け取るので **not_fixed** にしました。

## 4. 署名の分離

- 人の署名のひな形は [label_signoff_holdout_v4.template.json](label_signoff_holdout_v4.template.json)（`label_set: "holdout_v4"`）です。署名の本体（`label_signoff_holdout_v4.json`）は人が作ります。AI は作りません。
- `require_label_signoff(..., label_set="holdout_v4")` は、`holdout_v4_truth.json` の SHA-256 と `label_set: "holdout_v4"` の両方がそろわないと開きません。v1・v2・v3 の署名では開かず、v4 の署名でも v1〜v3 は開きません（`tests/evaluation/test_holdout_set.py` の `TestHoldoutV4Set`）。
- `holdout-v4-` のケースは、実行器（`aegis/evaluation/evaluation_runner.py` の `run_case`）で必ず `holdout_v4` の署名に結び付きます。正解のファイルは、署名の確認のためにハッシュを取るだけで、計画器・判定器には渡しません。
- 実行：`VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.run_model_evaluation compare --set holdout_v4`（出力は `comparison_holdout_v4.json`）。凍結の後に1回だけ実行しました（下の「結果」）。

## 結果の読み方（独立レビューを受けて追記）

- **特異度 1.00 の意味**：採点では、判断不能のまま残った負例も TN（真陰性）に数えています。そのため、特異度 1.00 が意味するのは「誤検知がなかった」ことだけです。負例23件のうち、凍結した判定器が実際に「不成立」（または仕様が必要）と**判定できたのは6件**でした（005・008・013・023・033・036）。残りの17件は判断不能です。判断をしない固定 L1 も、特異度は同じく 1.00 になります。
