# 未見30ケースの正解ラベル：人によるレビュー用シート

2026-11-21 作成。**このレビューが終わり、署名（`docs/evaluation/label_signoff.json`）が保存されるまで、実モデルによる評価はできません**（`aegis/evaluation/evaluation_runner.require_label_signoff`）。署名には、人の名前、完了日、`holdout_truth.json` の SHA-256、不一致がすべて解消されたことが必要です。ラベルのファイルを1文字でも変えると、署名は無効になります。

モデルには、このシートも正解も渡しません。モデルが見るのは、診断状態の ID と短い語だけです（`docs/evaluation/requests.jsonl`）。

## 判定の基準

- **他アカウントの読み取り（other_account_read）**
  - 成立：A が実際に B の機密の記録を受け取り、かつ所有者の規則が「認証必須」
  - 不成立：A が B の記録を受け取らない、または規則が「公開」
  - 仕様が必要：A が B の記録を受け取るが、読み手を定めた規則がない
  - 範囲外：ルートが資源への Link ヘッダーを返さない
- **認証なしの露出**：上と同じ基準で、匿名の要求について判定します。
- **保留が妥当（withhold_ok）**：どの検査者が集められる証拠でも決められないもの。例：所有者本人の対照がない、常に429が返る。

## 署名の書き方

`docs/evaluation/label_signoff.template.json` をコピーして `label_signoff.json` とし、次を記入してください。

- `reviewer`：人の名前
- `completed`：完了日
- `labels_sha256`：`shasum -a 256 tests/evaluation/fixtures/holdout_truth.json` の値
- `disagreements_resolved`：不一致をすべて解消したら `true`

ラベルを修正する場合は、修正した後の SHA-256 で署名してください。署名は所有者が自分でコミットします。AI は署名を作りません。
