# 統合版のローカルブラウザ回帰

PR #85 の `6475549` を基点に、専用QA作業ツリーで測定した。対象は隔離されたローカル模擬サイトで、DNS応答とループバック許可は測定プロセス内だけで置換した。実DNS、実サイト、有料モデルへは通信していない。実行器はARTEX互換代役で `engine_kind=unverified`、モデル呼び出し0。実ARTEX本体のE2Eとは区別する。

統合ブランチ `f4de821` でも表の4条件を再実行し、すべて成功した。390pxの再接続は2回、レポートに証拠ID、失効後の旧所見非表示は7.812秒、SSE遮断時の無通知変更回収は7.806秒。1280pxの組織切替では元の所見が他組織に表示されず、戻すと再表示した。API要求は順に24・16・28・20件で、いずれもページエラー0。診断時間は全体バックエンド回帰と並行した単発値であり、性能改善率には使わない。

| 条件・再現オプション | 観測 | 限界 |
| --- | --- | --- |
| `--block-events --silent-change`（390px） | SSEを遮断しても8操作で結果へ到達。無通知の所見変更を7.806秒で回収。API要求24件、ページエラー0 | 再接続でなく代替ポーリングの確認 |
| `--reconnect-events --report-export`（390px） | 最初のSSE接続を切断後、2回目が接続。Markdownをブラウザでダウンロードし、所見の証拠IDとプレビューを確認。API要求16件、ページエラー0 | レポート内容の全項目を監査したわけではない |
| `--org-switch --viewport-width 1280` | 同じアカウントで別組織へ切替。別組織の対象URLとassetが元の組織と異なり、元のApache所見は表示されない。元の組織に戻すと所見が再表示。API要求28件、ページエラー0 | 両組織が同じ固定ID `scan_001` を持つローカル条件。全権限組合せは未評価 |
| `--reconnect-events --revoke-session`（390px） | SSE接続3回、セッション失効後に旧所見が7.809秒で非表示。API要求20件、ページエラー0 | 失効時間はローカル単発測定 |

再現は `VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_browser_owned_flow --production --chromium` に表のオプションを追加する。事前に `web/` で `npm ci` と `npm run build` が必要。新しい `--reconnect-events` と `--block-events` の併用は拒否する。

修正後再確認は別の隔離ラボで `VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_browser_lab_recheck` により検証した。事前に `web/` の `npm ci` と `npm run build` が必要。ループバックの脆弱ラボで既存の承認経路を通してIDORを `proven`（HTTP 200）とした後、390pxの実ブラウザで「防御パッチ適用・再検証」を押した。結果は `not_reproduced`（HTTP 403）で、詳細画面に修正前後の異なる証拠ID、展開した証拠本文のHTTP 200と403、最新の「今回のアクセスは拒否されました」が表示された。横スクロールとページエラーは0。最新の応答には `confidential_marker` が含まれなかった。これは同梱ラボの模擬パッチだけの検証で、実サイトの修正確認や一般的なIDOR診断精度を示さない。

公開βの実DNS所有確認・実サイトE2E、実モデルの品質は未評価。
