# A2B（App-to-Backend）診断モードの設計：初期版は静的解析のみ

2026-11-19 JST。この初期版の範囲は次のとおりです。

- 所有者が提供したAPK、またはソースを**静的に読む**だけです。
- 抽出したAPIへの通信、アプリの実行、外部ツールの起動は行いません。

## 1. 原則

1. **アプリからAPIを見つけたことは、そのAPIへ通信してよい根拠になりません。** ホストごとに、既存の所有確認（DNS TXTなど）と診断範囲の承認を必要とします。
2. **静的解析の結果は、すべて「候補」です。** 「脆弱」とは書きません。
3. **秘密情報の値は出力しません。**
   - 出力するのは種類と場所だけです。
   - 照合用の指紋は、組織ごとの鍵（`fingerprint_key`）を渡したときだけ、HMAC-SHA256の先頭12桁を出力します。鍵なしの単純なハッシュでは、短いパスワードを総当たりで確かめられてしまうためです。
   - URLに含まれる認証情報は、出力前に取り除きます。
   - パスの一部に秘密情報が含まれる場合は `{secret}` に置き換えます。対象は、検出した秘密値と、英字と数字が混ざった20文字以上の不透明な値です（例：Slack・DiscordのWebhook、Telegramのbotトークン、`sk_live_`）。
4. **実サイトでのL2は引き続き禁止です。** 実サイトで後続にできるのは、既存の読み取り専用L1のGETだけです。IDORの再現は隔離ラボでのみ行います。SSRF、SQLi、RCEなどの侵入の実証は初期版では行わず、人による確認の対象とします。

## 2. 構成

| ファイル | 役割 |
| --- | --- |
| `aegis/a2b/manifest.py` | 提出の記録（SHA-256、サイズ、組織、提出者、所有の申告）と入力の上限 |
| `aegis/a2b/static_analyzer.py` | ZIP、DEX、テキストを上限付きで読み、URL、パス、HTTPメソッド、認証の手掛かり、秘密情報を抽出 |
| `aegis/a2b/endpoint_inventory.py` | エンドポイントの正規化（ID → `{param}`）、外部SDKホストの分離、OpenAPI定義との照合 |
| `aegis/a2b/risk_mapper.py` | 候補の分類と、次に行えることの制限 |
| `aegis/a2b/report.py` | 毎回同じ結果になるレポート（`report_sha256`）。`network_requests: 0` |

### 処理の流れ

1. 提出を記録します。所有者であることの申告がなければ拒否します。記録とファイルのハッシュが一致しない場合も拒否します。
2. 静的に読みます。
   - **APK**：メモリ上でZIPを読みます（ディスクへは展開しません）。
     - 次のメンバーは読み飛ばし、その旨を記録します：パストラバーサルを含む名前、圧縮率200倍を超えるもの、64MBを超えるもの。
     - バイナリXML（AndroidManifest など）は読みません。
     - DEXからは文字列表だけを取り出します。Retrofitの注釈は、コンパイル後も `users/{id}` のような文字列として残るため、ここから拾えます。
   - **ソース**：シンボリックリンクは辿りません。`node_modules`、`build`、隠しディレクトリは除外します。ファイル数とファイルサイズに上限があります。
3. エンドポイントを一覧にします。外部SDKのホスト（googleapis、firebase など）は別の一覧に分けます。ベースURLが1つしかない場合だけ、相対パスをそのホストに対応付けます（`host_inferred: true`）。
4. OpenAPI定義が提供されていれば照合し、次の3つに分けます。
   - 定義と一致したもの
   - 定義にないもの
   - 定義にはあるがアプリで見つからなかったもの
5. 候補を分類します。

   | 分類 | 内容 |
   | --- | --- |
   | `bola_candidate` | 利用者ごとの資源をIDで指定するAPI |
   | `auth_candidate` | 管理用・内部用に見えるAPI |
   | `ssrf_candidate` | URLを受け取る引数がある |
   | `injection_candidate` | 検索や絞り込みの引数がある |
   | `unauth_access_candidate` | アプリ側に認証の手掛かりが見つからない |

6. 候補ごとに、次に行えることを決めます。

   | 条件 | 次の段階（gate） | 後続に許される操作 |
   | --- | --- | --- |
   | ホスト不明 | `host_unknown` | なし |
   | 所有確認がまだ | `ownership_verification_required` | なし |
   | 所有確認済み、かつL1で確認できる分類 | `scope_approval_required` | `existing_l1_read_only_get` |
   | 所有確認済み、かつBOLA | `scope_approval_required` | `isolated_lab_l2_idor_only` |
   | SSRF、インジェクション | `manual_review_only` | なし |

   どの候補でも `auto_contact: false` です。

## 3. 外部ツールの比較（初期版では採用しない）

| ツール | ライセンス | 対応形式 | 安全性・負担 | 判断 |
| --- | --- | --- | --- | --- |
| JADX | Apache-2.0 | APK、DEX → Javaソース | Javaの実行環境が必要。巨大なアプリではメモリを多く使う。Workerとして隔離実行が必要 | 第2段階の候補。ソースまで戻すと、Retrofitのメソッドと引数の対応が正確になる |
| Androguard | Apache-2.0 | APK、DEX、AXML | Pythonで書かれ、ライブラリとして取り込める。ただし依存が多く、悪意あるAPKを解析すると例外やメモリ消費が大きくなるおそれがある | 第2段階の候補。AndroidManifest（exported、network security config）の解析に使う |
| MobSF | GPL-3.0 | APK、IPA など | 独立したWebサービスとして動き、範囲が広い。動的解析の機能も含むため、隔離と無効化の設計が必要 | 当面は不採用。Vulnix本体に組み込まない |

初期版は標準ライブラリだけで実装しています（`zipfile`、`struct`、`re`）。

- **利点**：通信や外部プロセスの起動をしないことを、テストで確かめられます。
- **代償**：Retrofitのメソッドと引数の対応（`@Query` の名前など）が取れません。iOS（IPA）とFlutterのスナップショットも読めません。

## 4. 検証（`tests/test_a2b_static.py`、`test_a2b_inventory.py`、`test_a2b_scope.py`：26件、すべて成功）

| 合格条件 | 結果 |
| --- | --- |
| APK解析中の外部通信が0件 | PASS。解析中に `socket.connect`、`create_connection`、`getaddrinfo`、`urlopen`、`subprocess.Popen` が呼ばれたら失敗するようにして、APKとソースの両方を解析しました。呼び出しは0回です。さらに、`aegis/a2b` が通信やプロセス起動のモジュールを import していないことを、構文解析で確認しています |
| 秘密値をログやレポートに出さない | PASS。Google APIキー、AWSキー、`client_secret`、URLに含まれる認証情報のいずれも、レポートに値が含まれないことを確認しました |
| 抽出したAPIへ自動接続しない | PASS。全候補が `auto_contact: false`、`network_requests: 0` です |
| 同じアプリを再解析すると同じ結果になる | PASS。`report_sha256` を含め、結果が一致しました |
| 未確認のAPIを「脆弱」と断定しない | PASS。全候補が `status: candidate` で、断定語は0件です |
| 所有確認の前に診断を起動しない | PASS。未確認のホストでは `allowed_followup` がすべて `none` です |
| 実サイトL2の禁止を維持 | PASS。後続は既存のL1、または隔離ラボのIDORだけです |
| 悪意ある入力への耐性 | PASS。ZIP爆弾、パストラバーサル、壊れたDEX、ZIPでない入力、シンボリックリンク、CRCエラー・暗号化・未対応の圧縮方式のメンバー、FIFOなどの特殊ファイル、不正なIPv6 URLを確認しました。DEXは同じ文字列を指す項目を1回だけ読み、文字列1件4KB・合計32MBが上限です。正規表現の一致数は `islice` で上限を設け、JWTの長さにも上限があります |

**検証用のアプリ**（`tests/fixtures/a2b/sample_app`）：架空のKotlin Retrofit、React Nativeのバンドル、設定JSONで構成しています。ホストは予約TLDの `.test` で、秘密情報も架空の値です。期待するエンドポイント9件は、すべて抽出できました（`expected_endpoints.json`）。
