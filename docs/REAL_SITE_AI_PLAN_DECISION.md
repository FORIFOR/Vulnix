# 実サイト向け AI 計画の判断（2026-11-15）

## 現在の実動作

公開版の実サイト診断は、所有確認と範囲確認の後、公開ページを1回取得して設定を調べる読み取り専用の処理です。診断手順は内蔵ルールで決まり、ARTEX 本体は実サイトの計画に使用しません。IDOR や SQL インジェクションは実サイトでは検査せず、ラボ固有の候補は実サイトの結果に出しません。`VULNIX_REAL_SERVICE_DIAGNOSIS=l1` は L2・ARTEX・修正後再検証を拒否します。

個別所見のAI解説には、運用者が `VULNIX_REAL_SITE_SAFE_AI=1` を明示的に設定した場合だけ使う経路をDraft PRで追加しました。モデルへ送るのは匿名参照IDとコードで固定した規則・分類・深刻度・判定・判定根拠・CVE ID・丸めた点数・KEV真偽だけです。質問文、対象名、URL、証拠、応答本文、認証情報は送信しません。送信前の監査記録が失敗したら送信せず、出力は許可済みの主張・修正案カタログで検証します。初期状態では無効であり、本物の有料APIと実サイトでの動作は未確認です。

## ARTEX をそのまま有効化できない理由

ARTEX の複数ターン計画はモデル呼び出しを前提とします。対象 URL、取得した応答、所有者情報、証拠を含む要求を外部モデルへ転送すれば、サイトの情報を第三者へ送信します。既存の Planner LLM Gateway は実サイト名を含む要求を遮断し、ARTEX はローカルラボ以外を拒否します。計画項目の実行権限も ARTEX には与えず、Gateway に限ります。この遮断を緩めて実サイトで ARTEX を起動することはしません。

## 将来の成立条件

実サイト固有の AI 計画を導入するなら、対象情報を外へ送らないモデルを隔離環境内に置き、送信経路のないことを実測で確認する方法が候補です。必要最小限の入力だけを渡し、モデル出力を不信データとして検証し、Gateway の範囲制限・所有確認・承認分離・緊急停止を維持します。ローカルモデルの品質、隔離、プロンプト汚染、計画の妥当性、診断精度を別途評価する必要があります。現時点でその実装と評価はありません。

外部の Abliteration AI を実運用で使うには、対象所有者による送信同意、実モデルでの品質・機密除去の検証、利用回数・費用上限の確認が残っています。今回の修正では有料 API 呼び出しも実サイト通信も行いません。
