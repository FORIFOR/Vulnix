## PR #85・対象サイトが新規発行したSet-Cookie秘密値の非保存（2026-11-19 JST）

読み取り監査で指摘された未修正P2候補（`http_probe` Worker の JSON が生の `Set-Cookie` 値を含み、`AssessmentService` が事前登録済みL2秘密トークンしかマスクしないため、新規発行された認証セッションCookie値が `evidence[].content`・`state.json`・`audit.jsonl` の `stdout_preview`・非匿名Remotion出力に残り得る問題）を再現・修正した。

- **修正前失敗の再現**: ローカルHTTPS模擬サイトから `Set-Cookie: session=CANARY_SECRET_VALUE_9f8e7d6c5b4a; Expires=Wed, 21 Oct 2026 07:28:00 GMT; HttpOnly; Secure; SameSite=Lax` および引用符内セミコロンを含む `auth="CANARY_QUOTED_\"SECRET;Secure\"_VALUE"; Path=/; Secure; SameSite=Lax` を返し、Gateway→Worker→`AssessmentService`→`snapshot()` を実行したところ、`snap_json` 内の `evidence[].content` に両秘密値が含まれて赤テストが失敗することを確認した。
- **多層防御の実装**:
  1. `aegis/workers/http_probe.py`: `headers` マップから `Set-Cookie` / `Set-Cookie2` を除外し、`set_cookies` には各ヘッダーを個別に保持したまま Cookie値を `[REDACTED]` に置換し、名前（最大64文字）と検査用属性（`Secure`, `HttpOnly`, `SameSite`, `Max-Age`, `Path=/|[set]`, `Domain=[set]`, `Expires=[set]`, `Partitioned`）だけを出力する `sanitize_set_cookie_header()` を適用。引用符内のセミコロンを属性区切りと誤認しない `_split_cookie_parts()` を実装した。
  2. `aegis/service_diag.py`, `aegis/gateway.py`, `aegis/assessment.py`, `aegis/evidence.py`: Gatewayの監査記録前、`AssessmentService._exec` の証拠保存前、および `enforce_verdict()` での過去データ読み込み時に `sanitize_http_probe_payload()` を適用。さらに `secret_redactor` が例外や非文字列を返した場合は安全側に拒否（fail-closed）するよう強化した。
- **修正後検証**: `tests.test_cookie_purpose_lab` 全10件、`check_cookie_ui_390`、`check_cookie_https` がすべて成功し、snapshot・report・監査ログ・`state.json`・Remotion出力に秘密値が一切残らず、Cookie属性・重複属性不一致の診断精度が100%維持されることを確認した。
