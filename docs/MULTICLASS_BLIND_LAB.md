# 5分類の独立ラボ採点

`VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_multiclass` は既存のCORS、Cookie、認証・IDOR、Apache `mod_status` の隔離ラボを再実行し、同じTP/FP/FN/TN定義で採点する。正解は各ラボの診断器と分離した条件・仕様から取得する。認証とIDORは同じ14対象を共有するため、分類の条件数や通信回数を合算して「ユニーク対象数」と呼ばない。

| 分類 | 条件 | 固定 TP/FP/FN/TN | ARTEX計画 TP/FP/FN/TN | 範囲 |
| --- | ---: | ---: | ---: | --- |
| CORSポリシー | 5 | 1/0/0/4 | 未評価 | 資格情報付き未信頼Originの許可 |
| 認証セッションCookie属性 | 10 | 4/0/0/6 | 未評価 | 承認済み所有者仕様と属性 |
| 認証必須JSONの未認証公開 | 14 | 2/0/0/12 | 2/0/0/12 | 所有者仕様とGET応答 |
| 他アカウント資源のIDOR | 14 | 0/0/2/12 | 2/0/0/12 | `proven`には隔離ラボの対照実行 |
| Apache `mod_status` 情報露出 | 3 | 0/0/1/2 | 1/0/0/2 | 固定カタログの追加GET |

ローカル代役プランナーでの1回の再測定では、固定方式のMacro Recallは5分類で60%。比較可能な3分類だけに揃えると固定33.3%、計画経路100%。Macro Precisionは固定5分類のうち予測陽性がある3分類だけで100%、比較可能3分類の固定では1分類だけで100%。予測陽性のない分類のPrecisionは**未定義**であり、0%・100%に置き換えない。計画経路のMacro Precisionは比較可能3分類で100%。この小さな既知ラボ集合を一般Webサイトの精度とみなさない。

ARTEXの検査選択を比較できるのはIDORの14条件だけ。観測に応じたローカル選択の適合率は8/(8+1)=88.9%、Recallは8/8=100%、不要選択は1件。CORSとCookieにはARTEX選択の比較経路がなく、表の空欄を成功として計上しない。認証必須JSONは初回固定GETで判定されるため、計画経路の値が同じでもARTEXの貢献と主張しない。

ローカル再実行では`engine_kind=unverified`の代役プランナーが検査案を注入し、モデル呼び出しは0回。CIは既存のピン留めされた実ARTEXとローカル模擬モデルで認証・IDORとApacheの元ラボを走らせ、そのJSONを同じ採点器に渡した。`artex-binary`を確認し、分類別のTP/FP/FN/TNとMacro平均は上表と同じだった。実Abliteration AIの推論能力、採用率、実トークン、請求額は未測定。

通信・Worker・時間・予算用推定トークンは`source_scope`に元ラボ別に記録する。CORSとCookieの直接解析にはWorkerとモデルを起動していない。認証とIDORは同じ通信を共有する。費用は模擬モデルなので有料実費US$0であり、予算用推定値を実トークン・請求額と混同しない。

| ローカル代役経路の元ラボ | 固定 対象GET/Worker/合計時間 | 計画経路 対象GET/Worker/合計時間 |
| --- | ---: | ---: |
| 認証・IDOR共有14条件 | 14 / 14 / 1.004秒 | 29 / 23 / 8.759秒 |
| Apache 3条件 | 3 / 3 / 0.265秒 | 6 / 6 / 2.073秒 |

これは診断能力の増加と引き換えに通信・起動・時間が増えた測定であり、速度改善を示さない。ローカル代役では推定トークン0・有料費用0・モデル呼び出し0。CIの実ARTEX測定には別の予算用推定トークン値が出るため、このローカル値を実モデルの費用としない。

CIの実ARTEX＋ローカル模擬モデルの1回の測定：

| 元ラボ | 固定 対象GET/Worker/合計時間 | 実ARTEX計画 対象GET/Worker/合計時間 | ローカルモデル呼び出し / 予算用推定トークン |
| --- | ---: | ---: | ---: |
| 認証・IDOR共有14条件 | 14 / 14 / 1.724秒 | 29 / 23 / 19.303秒 | 37回 / 139,338 |
| Apache 3条件 | 3 / 3 / 0.437秒 | 6 / 6 / 4.232秒 | 6回 / 24,984 |
