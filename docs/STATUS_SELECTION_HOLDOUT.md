# Apache情報露出の選択・検出を分けた隔離ラボ評価

独立した模擬対象 `StatusExposureLab` と正解表 `tests/fixtures/status_selection_holdout_truth.json` を使う。5条件はApacheの実際の `mod_status` 露出、403、紛らわしい200、非Apache、追加GETの同意なしを含む。正解ラベル・条件ID・対象ホスト・URL・応答本文をARTEXまたはモデルへ渡さない。所有確認はローカルの模擬DNS応答で行い、実サイトには通信しない。

比較するのは固定診断、一律ARTEX提案、初期観測による選択である。追加GETはGateway・隔離Workerを通る。`check_appropriate` は署名済み同意とApacheの初期観測から検査が許されることを表し、脆弱性の存在を意味しない。同意なしの露出条件は実際に脆弱な模擬対象だが、Vulnixには検査権限がない。この条件は検査選択の安全性には含め、脆弱性検出のTP/FP/FN/TNからは除外する。

各戦略とも同意なし条件の追加GETは0回。時間は診断開始から結果までの合計で、証明書生成と所有確認の準備を含まない。ローカル互換プロセスは固定意図を直接受け取り、モデル呼び出しは0回である。Linux CIでは代表2条件を実ARTEXバイナリ＋ローカル模擬モデルでも実行し、JSON証拠を保存する。実Abliteration AIの判断能力、実サイトの精度、公開βの動作は未確認。

再現方法：`VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_status_selection_holdout`。CIの代表条件は `--smoke`。
