### 安全ゲート（この順に確認する）

| 順 | ゲート | 内容 |
| --- | --- | --- |
| 1 | SHAの照合 | 固定の要求をローカルで作り直し、そのSHA-256と承認のSHA-256を比べます（`hmac.compare_digest`）。一致しなければ、何も送らず、承認も消費しません |
| 2 | 鍵と監査 | サーバー側のAPIキーと、検証に成功する監査チェーンが必要です |
| 3 | 1回限りの消費 | 送信の**前に**、承認を使った記録を作ります（ディレクトリ0700の中に、`O_EXCL` で0600のファイルを作り、`fsync` する）。<br>2回目以降は、送信が失敗した後でも、別のプロセスからでも「消費済み」として拒否します。**再送はできません。**<br>消費の監査記録に失敗した場合は送らず、承認も消費済みのままにします |
| 4 | 予算の確保 | **検査選択**：`PlannerLLMGateway` が最悪の場合の費用を予約し、`planner_llm.forwarding` の監査記録を必須にします（上限：1回、20,000トークン、US$0.06）。<br>**日本語解説**：`AuditLog.record_with_budget` で最悪の場合の費用（US$0.013559）を予約します。予約の累計は、上限US$0.02を超えられません |
| 5 | 送る中身の確認（日本語解説） | 実際に送る直前に、本文のSHA-256と送信先を再確認します。2回目の送信は拒否します |
| 6 | 回答の採用 | 次の場合は不採用にします：`finish_reason` が `stop` 以外／usage が欠けている、片方しかない、予算を超えた／JSONが不正、または全条件を含まない。<br>モデルの返した文章は保存も返却もしません。返すのは集計値だけです |

### テスト（`tests/test_eval_approved_paths.py`、14件）

テスト中は `_external_transport` と socket を、呼ばれたら失敗するものに差し替えています。

| 確認したこと | 結果 |
| --- | --- |
| 固定SHAが資料に記載した値と一致する | 成功 |
| SHAが一致しない場合 | 送信0回、承認の消費0件 |
| 鍵がない、または監査が改ざんされている場合 | 送信0回 |
| 1回送った後 | 2回目は「消費済み」で拒否され、送信は1回のまま |
| 上流が失敗した場合 | 承認は消費され、再送できない |
| `length`／usage なし／予算超過／不正なJSON／一部の条件しかない回答 | いずれも不採用 |
| 監査の記録に失敗した場合 | 送信0回、その後も再試行できない |
| 承認ディレクトリの権限が広すぎる場合 | 拒否 |
| 日本語解説の累計予算の上限 | 守られる |
| 送る本文が改ざんされた場合 | 送信0回 |
