# 実サイト診断の計画：reachmade.com（所有確認と低負荷 L1 のみ）

**状態：計画のみです。** まだ reachmade.com には一度も通信していません。実行するには、所有者の承認が必要です。

## 対象
| 項目 | 内容 |
|---|---|
| ホスト | `reachmade.com`（`https://reachmade.com/`） |
| 構成（`~/Projects/reachmade` の設定から確認） | Cloudflare Workers（`worker.js`）。`./dist` の静的ファイルを配信し、問い合わせの保存に D1 データベース（`reachmade-inquiries`）を使用 |
| 所有者 | プロジェクトの設定に記載されているとおり、このリポジトリの所有者本人 |

## 1. 所有確認の方法（追加費用なし）
**推奨は A（DNS TXT）です。** サイトのコードもデプロイも変えずに済みます。

| 方法 | 手順 | 費用・影響 |
|---|---|---|
| **A. DNS TXT（推奨）** | Vulnix で `https://reachmade.com/` を「実サービス」として登録し、値を発行します → Cloudflare の DNS に TXT レコード `_vulnix-verify.reachmade.com` = 発行された値 を追加します（所有者が行います） | 無料。サイトの動作には影響しません。確認が終わったらレコードは削除できます |
| B. HTTPS ファイル | `public/.well-known/vulnix-verify.txt` に値を置いてビルドし、`wrangler deploy` します | 無料ですが、本番へのデプロイ（所有者の承認）が必要です |

- 確認のための通信は、**DNS の TXT 問い合わせ 1 回**です（B の場合は HTTPS の GET 1 回）。
- 発行する値は、診断を行う環境（開発用 VM のバックエンド、8787）の秘密値から作られます。公開β版では、実在サイトへの通信を無効にしているため、使いません。

## 2. 低負荷 L1 診断の計画
| 項目 | 内容 |
|---|---|
| 実行するもの | Vulnix の L1「公開設定の検査」だけです：**`GET https://reachmade.com/` を 1 回**（TLS ハンドシェイクを含む） |
| 見るもの | TLS の設定、セキュリティヘッダー（CSP、HSTS、X-Content-Type-Options など）、Cookie の属性、CORS、Server ヘッダーなど、応答に含まれる情報だけ |
| しないこと | フォームの送信（特に問い合わせ → D1 への書き込み）、ページの巡回（クロール）、ログインの試行、L2（実証）、ARTEX による計画、高頻度のアクセス |
| 負荷 | 1 回の GET です。Cloudflare の通常のアクセスと同じで、Workers の無料枠の範囲に収まります |
| データの扱い | 応答の内容は、Vulnix の手元（VM）にだけ保存します。**外部の AI には送りません**（実サービスのデータを外部 AI に渡さないのは、Vulnix の仕組みとしての決まりです）。解説は内蔵のものを使います |
| 止め方 | 予期しない応答（5xx、リダイレクトで別のホストへ移動するなど）があれば、そこで止めます。リダイレクト先を自動で診断範囲に加えることはしません |
| 結果の確認 | 根拠（証拠）、誤検知の可能性、リスク評価、修正方法、日本語の解説を確認し、報告します |

## 3. 承認していただきたいこと（実行時）
1. 所有確認のための TXT レコードの追加（所有者が行う）
2. reachmade.com への通信：所有確認（DNS 1 回）と L1（GET 1 回）
3. L2 は今回の計画に含めません。必要になった場合は、対象・操作・テストアカウントを示して、改めて承認をいただきます
