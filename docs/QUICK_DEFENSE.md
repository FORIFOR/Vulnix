# 個人開発者向けのかんたんセキュリティ検証

最優先は、個人開発者が自分のサービスについて、公開された攻撃に関係する防御を短時間で確認し、修正後に確かめ直せること。評価には、検証できる防御項目、未確認の根拠、開始までの操作数を使う。

## 一次資料

- A. [CrowdStrike — 韓国の金融機関を対象としたARTEX関連活動](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/)
- B. [CrowdStrike — VAPOR PANDA](https://www.crowdstrike.com/en-us/blog/vapor-panda-uses-artex-to-scale-global-campaign/)
- C. [CrowdStrike — エージェント型AIを使った4件のキャンペーン](https://www.crowdstrike.com/en-us/blog/crowdstrike-uncovers-new-agentic-ai-campaigns/)
- D. [Anthropic — Claude Codeを悪用した諜報活動](https://www.anthropic.com/news/disrupting-AI-espionage)

AはARTEX利用と侵害を報告するが、個々の被害環境の侵入経路は確定できない。Aに関する管理面・公開面の確認は、この報告から導く防御上の確認事項として扱う。ARTEXプランナーの接続はVulnixの実行経路の確認であり、対象サービスの耐性については個別の証拠が必要になる。

| 報告上の手法・リスク | 防御策 | 既存の検査と環境 | 安全に追加できる証拠 | 対応状況と次の確認 |
| --- | --- | --- | --- | --- |

| B 署名を検証しないSAML | 信頼したIdPの署名を必須化 | ローカルの設定監査 | SSO設定、既存の署名検証テスト結果 | 部分対応。結果の整理と再検証が可能。サービス固有の実効設定は要確認 |
| B 外部実体を許すXML処理 | 外部実体とDTDを無効化 | ローカルの設定監査 | パーサーと実効オプション | 部分対応。対応ライブラリごとの設定監査を追加する |

## 実装と測定

| 確認項目 | 状況 |
| --- | --- |
| ブラウザ内での設定証拠の分類と再検証 | 対応済み。根拠なし、根拠つき未対策、根拠つき対策、根拠つき対象外を分ける |
| EC2起動テンプレートのメタデータ保護 | 明示設定の静的照合は対応済み。条件式、実デプロイ、IAM権限は未確認 |
| npm依存関係の取得元 | lockfile v2/v3の明示HTTP取得元の照合は対応済み。取得先の実効動作と依存パッケージのCVE自動照合は未対応 |
| ソースコード | JavaScript系ファイルのHTML書き込み候補の提示に限定。データフロー判定は未対応 |

EC2の判定は [AWS CloudFormationのMetadataOptions仕様](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-properties-ec2-launchtemplate-metadataoptions.html) に基づく。

## 利用方法と結果の読み方

- **ローカルプロジェクト**。ダッシュボードから検証を開き、証拠JSON、任意のJavaScript系ファイル・npmロックファイルを選び、開始する。3分類が初期選択。ブラウザ内で入力を解析し、診断APIや外部宛先に送らない。CVEカタログはNVD JSONの読み込みでセッション中に差し替えできる。
- **Webサイト・API**。ダッシュボードから既存のウィザードを使う。既存許可の選択は従来のサーバーAPIを通る。Google Search Consoleと確認用ファイルを優先し、OIDCは詳細設定にある。結果は従来の診断画面に表示する。
- **模擬データと隔離ラボ**。「模擬データで試す」は3分類の判定を、用意した証拠で確認する。実行を伴うローカルラボは資産一覧から従来のワークスペースを使う。
- 防御確認済みは入力した根拠の範囲に限る。未確認と対象外は合格件数に含めない。対象外には理由が必要。ソース解析はHTML書き込みパターンの候補箇所までで、到達可能性や安全性は未確認。CVE一致は正準の製品・数値版の候補で、影響条件はベンダー勧告と実効設定に照らして確認する。

PR #127・#128のリリース阻害要因は [製品導線とリリース準備](PR128_PRODUCT_INTEGRATION.md) に記載している。


## ブラウザでの受入確認

新規ユーザーでサインアップ後、390px画面でダッシュボードを開き、ローカル入口、証拠JSON、ソース、npmロックファイル、開始の5操作で結果まで到達した。自動操作の経過時間は0.18秒。人が資料を探す時間やファイル選択ダイアログの時間は含まない。ARTEX 5件、CVE 2件、Claude Code 5件の計12件を表示し、防御確認済み1件、対策が必要3件、未確認8件と判定した。この固定入力では期待する分類に一致し、誤検出・見逃しは各0件。未知のプロジェクトや一般の検出精度は未評価。

利用者1人で根拠と修正方法を確認し、設定証拠を更新して再検証した。修正した認証項目は防御確認済みに変わり、別項目の残件は維持された。NVDのファイル取り込みと模擬データの結果表示も確認した。検証開始からこれらの画面操作中に診断通信は0件。模擬サイトでは、保存済み許可を使って所有確認の再発行なしにワークスペースを開けた。公開サービスの対策評価は、このローカル入力・模擬データの集計には含めない。
