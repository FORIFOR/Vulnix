# 5分類の保留用条件比較（隔離ラボ）

3つの独立した対象群を同じ固定・一律提案・観測選択で比較する。CORS・Cookieは既存応答とApache・同意の新しい組合せ5条件、Apache情報露出は陽性・403・紛らわしい200・非Apache・同意なしの5条件、認証必須JSON・IDORは別の模擬対象が返す保留用応答7条件である。正解表と所有者仕様は `tests/fixtures/` に分け、モデルに正解ラベル、条件ID、応答本文を渡さない。模擬ラボの対象識別子はARTEX経路で使うが、実サイトのホスト名・URLは使わない。認証とIDORは同じ7条件の対象GETを共有するため、通信回数は一度だけ数える。

各分類の検出判定と、Apache追加GET・IDOR再現を選ぶ判断を別に採点する。検査の「適用可能」は、同意・初期観測から安全に選べることを意味し、脆弱性があることを意味しない。同意がないApache露出は検査禁止なので、選択安全性の評価には含め、検出TP/FP/FN/TNから除外する。IDORの再現は隔離ラボ内だけで実行する。

対象GET・Worker・時間は3対象群の合計で、認証とIDORを重複加算していない。時間はローカル単発測定で、証明書・所有確認の準備は含まない。固定方式より観測選択は追加検査の分だけ遅い。一律提案と比較すると不要な提案7件、対象GET3回、Worker3回を減らした。**本物のAbliteration AIが判断した結果ではない。** ローカル互換プロセスのモデル呼び出し・推定トークン・課金は0で、実ARTEX＋ローカル模擬モデルの代表条件はLinux CIで別に記録する。各分類の陽性条件は1件程度であり、一般サイトや新しい脆弱性への精度を示さない。

再現方法：`VULNIX_NO_ENV_LOCAL=1 python3 -m scripts.bench_five_class_holdout`。結果JSONは各分類のTP/FP/FN/TN、Macro分母、選択精度、通信、Worker、時間、トークン・費用欄を保持する。
